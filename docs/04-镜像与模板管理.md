# 04 · 镜像与模板管理

## 1. 概念：基础盘与快照

```
$VHD_DIR/<VMID>/
├── vm-<VMID>-1.qcow2          # 基础盘（持久数据，对应 BOOT_INDEX=1）
├── vm-<VMID>-snapshot.qcow2   # 非持久模式的写时复制快照（每次开机重建）
└── ...
```

| 模式 | 行为 | 适用 |
|---|---|---|
| 持久（PERSISTENT=1） | 直接使用基础盘，改动保存 | 个人机、需要保留状态 |
| 非持久（PERSISTENT=0） | 启动前 `qemu-img create -f qcow2 -b <基础盘>` 生成快照，虚机只写快照 | 教室/展厅等"重启即还原" |

非持久模式的基础盘可以是 qcow2 也可以是 raw（qcow2 支持 raw backing），
因此空间紧张时模板可以不转换直接使用。

## 2. 模板从哪来

Windows 模板 = 在同构虚拟硬件上装好系统与驱动后打包的磁盘镜像：

1. 用 QEMU + EDK2 固件创建一台"金机"（virtio-blk/net/gpu + xhci，与部署目标一致）；
2. 安装 Windows 11 ARM64，装齐 virtio-win 驱动与集成工具（spice/qemu-ga 等按需）；
3. 系统准备（sysprep 按需）后关机，磁盘导出为 raw/qcow2，打包 `tar.gz` 并附 md5。

官方化的模板分发通常伴随三个文件：

```
windows11-arm64-YYYYMMDD.tar.gz   # 模板本体
md5.txt                            # 校验和
info.json                          # 虚拟盘大小等元数据（用于预估空间）
```

## 3. 导入流程（import-template.sh）

```
tar.gz ──解包──► 磁盘镜像（raw/qcow2）
        ──qemu-img convert──► $VHD_DIR/<VMID>/vm-<VMID>-<INDEX>.qcow2
        ──登记──► template.conf（current_system 等状态字段）
```

- 解包用 `pigz` 自动加速（存在时）；
- 空间不足自动退化为 raw 直用；
- 导入完成后 `qemu-img info` 打印最终布局。

## 4. 多系统与 A/B 切换

同一 VMID 下用 `BOOT_INDEX` 区分多块盘（`vm-<VMID>-1.qcow2`、`vm-<VMID>-2.qcow2`）：
启动脚本按参数选择盘，即可实现双系统切换。进阶做法（部分终端方案采用）：
GRUB 侧配合自定义模块直接识别 VHD，实现引导期的 A/B 系统与升级回滚。

## 5. 数据盘

三类典型做法（按需选择，`qemu-windows.sh` 中对应参数段）：

| 方式 | QEMU 形式 | 适用 |
|---|---|---|
| 虚拟盘文件 | 再挂一块 `-drive file=...qcow2` | 常规数据分区 |
| 物理整盘直通 | `-drive file=/dev/sdX,format=raw` + virtio-blk | 大于 64G 且宿主不挂载的空闲盘 |
| 宿主目录回环 | VHD 文件（如固定名 GUID.vhd）+ FUSE/loop 暴露分区 | Windows 与宿主共享数据 |

## 6. 备份与迁移

- 虚机全部状态 = 基础盘 + 快照链 + `template.conf`，拷贝即迁移；
- 备份建议在虚机关闭状态做（qcow2 内部一致性），或用 `qemu-img snapshot -c` 打内部快照；
- 导出分发用 `qemu-img convert -O qcow2 -c`（压缩）后打包。
