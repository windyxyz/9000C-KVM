# 01 · 架构总览

## 1. 方案定位

IDV（智能桌面虚拟化）与 VDI 的核心区别：**算力在终端本地**。

| | VDI（远程云桌面） | IDV（本地虚拟化） |
|---|---|---|
| Windows 运行位置 | 数据中心服务器 | 终端本地虚拟机 |
| 网络依赖 | 强断网不可用 | 弱仅管理需要 |
| 图形/外设体验 | 受网络制约 | 本地直通，接近原生 |

本项目的终端形态：一台 ARM64 终端（麒麟 9000C），硬盘上同时保留
原生系统（UOS/麒麟）与一个 IDV 宿主系统，开机由 GRUB 菜单选择。

## 2. 引导链全景（进入 Windows 的完整路径）

```
阶段① 引导
  UEFI 固件
    └─ GRUB（menuentry 指向宿主 /boot 中预先放置的内核与 initrd）
         linux /vmlinuz  rootimg_uuid=<分区UUID> rootimg_path=<目录> ...
         initrd /initrd.img

阶段② initrd（引导的"机关"所在）
  1. 解析内核参数中的分区 UUID 与镜像路径
  2. blkid 死循环等待该分区出现在 /dev（设备可能晚到）
  3. mount 该分区 → 定位 os.img（完整的宿主系统磁盘镜像文件）
  4. losetup -Pf 把 os.img 回环成块设备，ROOT = 其分区1
  5. mountroot → run-init 切换根

阶段③ 宿主系统启动（openEuler 底座）
  - fstab：把承载 os.img 的宿主分区挂回 /mnt 下（模板/虚拟盘/数据盘都在其上）
  - weston（Wayland 合成器）占据 tty1，作为虚机显示的"桌面"
  - 定制内核提供麒麟平台的 KVM、Wi-Fi、音频、GPU（Mali blob）等驱动

阶段④ 虚机启动
  - 导入服务把 Windows 模板（tar.gz）展开为 qcow2 虚拟盘
  - 启动脚本组装 QEMU 命令行并 -daemonize 后台运行
  - SDL 全屏窗口落在 weston 上，视觉上"直接进 Windows"

阶段⑤ Windows 内部
  - EDK2 ArmVirtQemu 固件 → Windows Boot Manager → Win11 ARM64
  - 全部设备为 virtio 半虚拟化，驱动来自模板内预装的 virtio-win
```

## 3. 为什么要"文件镜像引导"

把整个宿主根文件系统做成一个磁盘镜像文件而不是直接分区安装：

| 收益 | 说明 |
|---|---|
| 不破坏原系统 | 原生系统分区不动，os.img 只是一个大文件，卸载=删文件 |
| 可置换/可备份 | 换镜像、回滚、批量分发都是文件操作 |
| 引导解耦 | 内核/initrd 提出来放进宿主 /boot，GRUB 无需理解镜像内部 |

代价是引导需要"两段式"：GRUB 只能加载普通分区上的内核，
由 initrd 完成从"文件"到"根设备"的转换。

## 4. 启动时的关键配置

GRUB 菜单项（示例见 `examples/grub-file-image.conf`）向内核传递的最小信息集：

```
rootimg_uuid=<os.img 所在分区的 UUID>
rootimg_path=<os.img 相对该分区的路径>
```

initrd 据此定位镜像并切换根，其余（fstab、服务、虚机）全部由镜像内系统自理。

## 5. 组件职责速查

| 组件 | 职责 |
|---|---|
| 定制内核 | 麒麟平台驱动 + KVM（`/dev/kvm` 是虚机启动的硬前提） |
| initrd | 文件镜像 → 根设备的转换器 |
| weston | Wayland 合成器，虚机 SDL 窗口的宿主 |
| QEMU | 设备模型（virtio 全家桶）+ KVM 加速 |
| EDK2 固件 | 虚机的 UEFI，开源 Tianocore ArmVirtQemu 构建 |
| 导入服务 | Windows 模板 tar.gz → qcow2（一次性） |
| 自启动单元 | 开机后自动完成"导入（如需）→ 启动虚机" |
