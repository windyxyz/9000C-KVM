# 03 · 虚拟设备与性能

## 1. 两层设备模型（理解改动的边界）

KVM/QEMU 虚拟机的每个设备都有两半：

| 层 | 是什么 | 谁负责 | 决定什么 |
|---|---|---|---|
| **第 1 层：设备模型** | QEMU "虚拟出"的硬件（virtio-blk 盘、virtio-net 网卡、virtio-gpu 显卡、xhci USB 控制器…） | QEMU 二进制 | Windows 加载哪些驱动 |
| **第 2 层：后端数据** | 这些设备"背后"的数据/服务（qcow2 文件、NAT 网络、共享内存音频、USB 转发…） | QEMU 后端 + 宿主服务 | 设备背后有没有数据、功能是否可用 |

**结论：Windows 驱动加载只取决于第 1 层。** 只要虚拟硬件清单一致，
Windows 引导与驱动加载与宿主侧服务无关；改宿主服务只影响第 2 层（功能可用性）。

## 2. 设备清单与后端

| 设备 | 第 1 层（虚拟硬件） | 第 2 层（后端） | 备注 |
|---|---|---|---|
| 系统盘 | virtio-blk-pci | qcow2/raw 文件，`cache=writeback` + `aio=io_uring`（或 threads） | `l2-cache-size` 调大有利于大镜像 |
| 网络 | virtio-net-pci | QEMU 内置 user-mode NAT（`net=10.0.0.0/24` + `hostfwd` 端口映射） | 无需宿主任何网络服务 |
| 显示 | virtio-ramfb / virtio-gpu-pci | SDL 全屏窗口投到 weston（Wayland） | 固件阶段即有显示（ramfb） |
| 键鼠 | usb-kbd / usb-tablet / virtio-tablet | QEMU 内置 | |
| USB 外设 | qemu-xhci + usb-host | libusb 转发，支持 QMP 热插拔 | 标准形式需 hostbus/hostaddr |
| 固件 | EDK2 ArmVirtQemu（`-bios QEMU_EFI.fd`） | 开源 Tianocore 构建 | |
| 声音（方案 A） | ivshmem-doorbell | 宿主共享内存音频服务 | 标准设备，延迟低 |
| 声音（方案 B） | intel-hda + hda-duplex | QEMU 音频后端（pa/sdl） | Windows 用内置 HDA 驱动 |
| 蓝屏自愈 | pvpanic-pci | QMP 监听 GUEST_PANICKED 自动重启 | |
| 主机↔虚机通道 | virtio-serial | 字符设备 socket | 剪贴板/文件等集成通道 |

## 3. 性能优化点（本方案做过的）

1. **CPU**：`-cpu host` 直通宿主核心；vCPU 数按物理核拓扑计算（SMT 兄弟算 1 核）；
   启动前把 cpufreq governor 切到 `performance`。
2. **内存**：按宿主物理内存分档预留（2/4/6/8/12/16/20/30G）；
   memory balloon 理论上更灵活，但实测易把虚机压进 swap，此方案选择固定预留。
3. **磁盘**：virtio-blk + `cache=writeback` + `aio=io_uring` + 增大 `l2-cache-size`；
   非持久场景用 qcow2 backing chain，持久场景直接用基础盘。
4. **显示**：SDL 直连 Wayland 合成器，虚机帧缓冲无额外拷贝路径。
5. **USB 直通**：`qemu-xhci` + libusb；需要热插拔时通过 QMP `device_add`。

## 4. GPU 现状与天花板

宿主侧 GPU（Mali/海思 blob）负责 weston 合成与 SDL 窗口，**显示输出走 GPU**；
但 Windows 虚机内部**没有 3D 加速**，原因（在此类 ARM 平台上的普遍现状）：

1. 平台没有面向 Windows 的 Mali/海思 WDDM 驱动（这类机器从无官方 Windows 支持）；
2. 集成 GPU 不具备 VFIO 整卡直通的隔离条件，且直通后同样无 Windows 驱动；
3. Virgl/Venus 等 GPU 半虚拟化仅支持 Linux 客户机（Windows 无对应驱动）。

因此实际效果：桌面、办公、网页、视频播放流畅；3D/游戏受 CPU 软渲染限制。
这是所有同类 ARM IDV 方案的共同天花板，不是配置问题。

**务实的图形优化**：
- 分辨率与虚机 `virtio-ramfb xres/yres` 保持一致，避免额外缩放；
- 视频播放优先用硬解可用的播放器路径（CPU 软解时降低码率预期）；
- 显卡异常排查用救援模式（`-device ramfb` + `QEMU_EFI_ramfb.fd`）。

## 5. 网络

启动脚本默认 user-mode NAT（slirp）：

```
-netdev user,id=n1,net=10.0.0.0/24,host=10.0.0.1,hostfwd=tcp::8022-:22,hostfwd=tcp::3389-:3389
-device virtio-net-pci,netdev=n1
```

优点：零宿主配置、离线可用；缺点：吞吐低于 tap/bridge。
需要更高网络性能时切换 tap + br0（宿主需配网桥），Windows 侧驱动不变。
