# 02 · 部署教程

> 目标：在一台已能引导 IDV 宿主系统（openEuler 底座）的 9000C 上，
> 部署"开机自动进入 Windows 11 ARM"的完整链路。
> 全程在宿主系统内操作（本机 tty 或 `ssh root@<IP>`，宿主镜像默认开启 sshd）。

## 0. 前提

| 项 | 要求 |
|---|---|
| 宿主镜像 | 已可从 GRUB 引导进入的 IDV 宿主系统（定制内核提供 `/dev/kvm`） |
| Windows 模板 | 预装好 virtio 驱动的 Win11 ARM 磁盘镜像打包（tar.gz），虚拟盘大小约 55GB |
| 磁盘空间 | 安装分区空闲 ≥ 模板虚拟盘大小（转 qcow2 峰值需约 2 倍，脚本空间不足时自动改用 raw） |
| QEMU | 宿主内可用的 `qemu-system-aarch64`（含 KVM 加速与 virtio-gpu/ramfb 设备支持） |

## 1. 确认虚拟化可用

```bash
ls -l /dev/kvm          # 不存在 = 内核不是本平台定制内核，先解决引导
qemu-system-aarch64 --version
```

## 2. 放置部署脚本

```bash
mkdir -p /opt/win-vm
cp import-template.sh qemu-windows.sh attach-usb.py /opt/win-vm/
chmod +x /opt/win-vm/*
```

> 脚本均为参数化通用实现，路径通过顶部环境变量适配你的宿主布局
> （`VHD_DIR` 虚拟盘目录、`EFI_FILE` 虚机 UEFI 固件、`QEMU_BIN` QEMU 路径）。
> 需要的固件文件为 EDK2 ArmVirtQemu 构建（`QEMU_EFI.fd`，2MB）。

## 3. 导入 Windows 模板（一次性，最耗时）

```bash
/opt/win-vm/import-template.sh /路径/windows11-arm64.tar.gz win11-local
```

脚本行为：
1. `tar` 解包模板（有 `pigz` 则自动加速），识别包内最大文件为磁盘镜像；
2. `qemu-img info` 探测格式；
3. 空间充足 → `qemu-img convert` 转 qcow2；空间紧张 → 直接以 raw 盘使用；
4. 产物：`$VHD_DIR/win11-local/vm-win11-local-1.qcow2`。

## 4. 注册开机自启动

```bash
cp windows-vm.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now windows-vm
```

自启动单元调用启动脚本，逻辑：

```
若无已导入虚拟盘 → 按 new_template.json（或手工配置）自动导入模板
随后调用 qemu-windows.sh → SDL 全屏窗口出现在 weston 上
```

`reboot` 验证完整链路：GRUB → 宿主启动 → weston → 数秒后全屏 Windows。

## 5. 参数协议

启动脚本参数：`qemu-windows.sh <VMID> <PERSISTENT> <BOOT_INDEX> <RESCUE_MODE>`

| 参数 | 含义 | 示例 |
|---|---|---|
| VMID | 虚拟盘标识，对应 `$VHD_DIR/<VMID>/` | `win11-local` |
| PERSISTENT | `1`=持久（改动保存）；`0`=非持久（qcow2 快照，重启还原） | `1` |
| BOOT_INDEX | 盘编号后缀（支持同 VMID 多盘 A/B 切换） | `1` |
| RESCUE_MODE | `1`=救援模式（ramfb 显示 + ramfb 固件，显卡异常时排查用） | `0` |

## 6. 日常操作

| 操作 | 命令 |
|---|---|
| 手动启停 | `systemctl start/stop windows-vm` |
| 实时日志 | `tail -f /var/log/win-vm.log` |
| USB 设备直通 | `python3 attach-usb.py list` → `add <bus> <addr>` |
| 多系统模板 | `import-template.sh <另一个模板包> <新VMID>` 后改 service 中 VMID |
| 远程桌面 | QEMU user 网络已映射 3389 → Windows |

## 7. 回退

自启动是纯增量部署：`systemctl disable --now windows-vm` 即回到宿主原状态；
删除 `/opt/win-vm` 与虚拟盘目录即完全卸载，不触碰宿主系统其他部分。

## 8. 排错速查

| 症状 | 处理 |
|---|---|
| `/dev/kvm` 不存在 | 引导的不是含定制内核的宿主镜像 |
| QEMU 报未知设备 | QEMU 版本过旧或缺模块目录，核对 `virtio-ramfb`/`qemu-xhci` 支持 |
| 黑屏但有 QEMU 进程 | 用救援模式（第 4 参数=1）排除显卡；核对分辨率变量 |
| 虚机内无声音 | 确认宿主音频服务在跑，或改用 `-device intel-hda -device hda-duplex`（Windows 内置驱动） |
| Windows 关机后宿主没关机 | 关机联动依赖标记文件机制，见 `qemu-windows.sh` 尾部注释 |
